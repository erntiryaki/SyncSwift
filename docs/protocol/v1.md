# SyncSwift Wire Protocol v1 Specification

## 1. Overview
SyncSwift v2 is a zero-knowledge, peer-to-peer and cloud-assisted multi-device sync protocol.
The protocol is designed to operate seamlessly across three communication topologies:
1. **Direct LAN Mesh** (mDNS discovery + mutual authenticated TLS/ChaCha20 over raw TCP)
2. **WebRTC P2P DataChannels** (STUN/TURN NAT traversal mediated by self-hosted Coturn on VPS)
3. **Encrypted Asynchronous Relay** (S3-compatible temporary chunk storage backed by self-hosted MinIO on VPS)

---

## 2. Cryptographic Primitives
- **Device Identity & Signing:** Ed25519 (RFC 8032)
- **Key Agreement (Diffie-Hellman):** X25519 (RFC 7748)
- **Symmetric Authenticated Encryption:** XChaCha20-Poly1305 (24-byte nonce, 16-byte MAC)
- **Key Derivation (KDF):** BLAKE3 / HKDF-SHA256
- **Content Hashing:** BLAKE3 (merkle tree chunk digests)

---

## 3. Handshake & Session Establishment
Every connection starts with a cryptographic mutual handshake:
```
Client A                                                         Client B
   |                                                                |
   | --- HELLO (ProtocolVersion, EphemeralPubKeyA, NonceA) -------> |
   | <--- HELLO_REPLY (EphemeralPubKeyB, NonceB, SignatureB) ------ |
   | --- AUTH (SignatureA, DeviceIdA) ----------------------------> |
   |                                                                |
   | === Handshake Complete (Shared Session Secret Derived) ======== |
```

---

## 4. Chunk Framing & Streaming
Payloads are split into 1 MiB (1,048,576 bytes) chunks:
```
+-------------------------------------------------------------+
| Header: 32 bytes                                            |
|   - Magic (4 bytes): 0x53574946 ("SWIF")                    |
|   - TransferId (16 bytes UUID)                              |
|   - ChunkIndex (4 bytes, uint32)                            |
|   - TotalChunks (4 bytes, uint32)                           |
|   - PayloadSize (4 bytes, uint32)                           |
+-------------------------------------------------------------+
| Nonce (24 bytes): XChaCha20-Poly1305 nonce                  |
+-------------------------------------------------------------+
| Encrypted Payload (PayloadSize bytes, up to 1 MiB)          |
+-------------------------------------------------------------+
| Auth Tag (16 bytes): Poly1305 MAC                           |
+-------------------------------------------------------------+
```

---

## 5. Self-Hosted Infrastructure Roles
- **Self-Hosted Supabase (VPS):**
  - PostgreSQL with RLS and `SECURITY DEFINER` RPCs.
  - Sign-in / session tokens, paired device registry, device presence, signalling metadata.
- **Self-Hosted MinIO (VPS):**
  - S3-compatible chunk storage for offline devices and personal vault backups.
  - Chunks stored in MinIO are always client-side encrypted before upload.
- **Coturn TURN/STUN (VPS):**
  - WebRTC ICE candidates relay when devices are on separate restrictive symmetric NATs.
